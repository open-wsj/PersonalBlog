> 机器学习笔记的第八篇。前面几篇讲的是模型本身，这篇讲的是**判断模型好不好、以及不好时往哪改**。这两件事在实战里比模型结构更常决定成败——很多人能写出一个网络，却说不清该把力气花在拿更多数据上，还是花在加特征上。

### 一、三个数据集，三种职责

一个模型在训练集上表现好毫无意义，真正要回答的是「在没见过的数据上表现如何」。为了把这个「没见过」量化，数据要分三份：

| 数据集 | 用途 | 数据是否参与训练 | 能否用来调参 |
| --- | --- | --- | --- |
| 训练集（train） | 拟合参数 $w$ | 是 | — |
| 验证集（valid / dev） | 选超参数、选模型、早停 | 否（只看不学） | **可以** |
| 测试集（test） | 最终报告泛化能力 | 否 | **不可以** |

关键在最后两列。**验证集的作用是让调参有一个不泄漏的反馈信号**：你在验证集上比较不同的 $\lambda$、不同的模型、不同的特征集，选最好的那个。而一旦这个选择过程反复参考了某份数据，这份数据就已经「被间接拟合」了，它对模型能力的估计会偏乐观。所以需要一份在整个调参过程中**一次都不碰**的数据来做最终评估，这就是测试集。

一个常见的错误做法：

```
for 每个超参数组合:
    在测试集上评估，选最好的
报告那个最好的分数
```

这等于用测试集调参，报出来的数字必然偏乐观，在真实业务上会掉一大截。正确结构是：

```
for 每个超参数组合:
    在验证集上评估，选最好的
用选出的配置在 train+valid 上重训（可选）
在测试集上评估一次，作为最终报告
```

### 二、怎么划分

**1. 留出法（hold-out）**

最简单的 `train_test_split`。三个比例建议：

-   数据量大（>10 万）：60/20/20 或 98/1/1 都可以，只要验证集够大到统计稳定；
-   数据量中等（几千~几万）：70/15/15；
-   数据量小（<1000）：留出法本身不可靠，改用交叉验证。

分类任务一定要 **stratify**，保证各集合的类别比例与整体一致，否则小类可能在验证集里只有一个样本，指标会剧烈抖动。

**2. K 折交叉验证**

把数据分成 $K$ 份，轮流用其中 $K-1$ 份训练、1 份验证，最后取平均：

$$
\text{CV} = \frac{1}{K}\sum_{k=1}^{K}\text{score}(f_{-k}, D_k)
$$

$K=5$ 或 $10$ 是常规选择。它的价值不只是给出一个更稳的分数，**还给出了分数的方差**——$K$ 折的分数标准差大，说明模型对数据划分敏感，本身就是高方差的一个信号。

**3. 嵌套交叉验证（nested CV）**

如果既要调超参数又要在同一批数据上得到无偏估计，需要两层：内层选超参数，外层评估。它计算代价是普通 CV 的 $K$ 倍，但在小数据上是最可信的做法。实践中很多人忽略了这一点，用普通 CV 选完超参数又用同一个 CV 分数当泛化估计，结果偏乐观。

**4. 时间序列必须按时间切**

随机划分会让「未来」的数据进入训练集，这在时序任务上是严重泄漏。正确做法是用前面的时间段训练、后面的验证（walk-forward），或者用 `TimeSeriesSplit`。

### 三、数据泄漏：比划分方式更常见的问题

即使比例划对了，泄漏依然会悄悄发生。几个高频场景：

**1. 在划分之前做了预处理**

`StandardScaler().fit_transform(X)` 之后再 `train_test_split`，测试集的均值方差泄漏进了训练。同样的坑还有：用全量数据做 PCA、用全量数据算目标编码、用全量数据填补缺失值。**正确做法永远是把预处理放进 Pipeline**。

**2. 重复样本跨集合**

同一个用户的多条记录被随机分到训练和验证两侧，模型其实见过这个人。这类问题在推荐、医疗、用户行为数据里极常见。要按**实体**（用户、患者、设备）分组划分，用 `GroupKFold`。

**3. 用未来信息构造特征**

比如用「该用户总消费额」做特征去预测某一次消费——这个总额本身包含了要预测的那一次。时序特征必须只使用预测时刻之前可得的信息。

**4. 目标泄漏**

某个特征是从标签直接推导出来的（比如「是否逾期」的衍生变量出现在预测逾期的特征里）。这种特征在训练集上和目标相关性极高，模型表现好得可疑，上线后完全失效。

**判断泄漏的一个实用信号**：如果验证分数**高得不像话**（比如 AUC 0.99、R² 0.995），第一反应不应该是高兴，而是去查是不是泄漏了。

### 四、基线的选择

很多人一上来就调复杂模型，结果不知道 0.78 的准确率到底算好还是差。**基线的作用是给分数一个参照系**。

#### 1. 平凡基线（必须做）

不看任何特征，直接用最简单的方法预测：

| 任务 | 平凡基线 |
| --- | --- |
| 二分类（均衡） | 随机猜，准确率 0.5 |
| 二分类（不均衡，正类 5%） | 全判负类，准确率 95% |
| 多分类 | 全判样本最多的类 |
| 回归 | 全预测训练集均值，看 RMSE |
| 回归 | 全预测中位数（对离群点更稳） |

这个基线经常能揭穿假象：一个 95% 准确率的模型在正类占 5% 的数据上，可能**还不如全判负类**。所以看到分类指标一定要先问「多数类占比是多少」。

#### 2. 简单模型基线

逻辑回归、线性回归、决策树、以及业务上已有的规则系统。如果复杂模型比逻辑回归只好 1%，那这个复杂度可能不值得——维护成本、推理延迟、可解释性都是代价。

#### 3. 人类水平 / 标注者一致性

在图像、文本这类任务上，人类准确率是一个天然的参考上界。更实际的是**标注者之间的一致性**：如果两个标注员在同一个样本上只有 85% 一致，任何模型超过 85% 就已经接近数据本身的上限，继续优化边际收益很低。

#### 4. 已有生产系统

如果是优化已有业务，当前线上效果就是最重要的基线。新模型必须带来可测的业务收益，而不是只在离线指标上好看。

一个重要提醒：**基线要在同一个测试集、同一套指标下比较**。用不同划分、不同阈值比出来的「提升」没有意义。

### 五、指标要和任务匹配

选错指标比选错模型更致命。

| 任务 | 常用指标 | 注意事项 |
| --- | --- | --- |
| 回归 | RMSE、MAE、MAPE、R² | RMSE 对大误差敏感，MAE 对离群点稳健 |
| 二分类 | 准确率、Precision、Recall、F1、AUC | 类别不均衡时准确率会骗人 |
| 二分类（概率） | LogLoss、Brier score | 关心概率是否可信时用 |
| 多分类 | macro / micro / weighted F1 | macro 让小类权重相同 |
| 排序 / 检索 | NDCG、MAP、Recall@K | 只关心前 K 个结果的质量 |

几个经常被混淆的点：

-   **AUC 衡量的是排序能力，不是概率校准**。AUC 高不代表预测概率能直接当风险概率用。
-   **类别不均衡时优先看 PR 曲线和 F1**，AUC 在极端不均衡下也会显得乐观。
-   **macro-F1 和 weighted-F1 在小类上差异巨大**，报告时要写清用了哪个。
-   **回归指标要先标准化**，否则不同目标尺度的任务无法比较。

### 六、偏差与方差：误差从哪来

现在进入核心。假设真实关系是 $y = f(x) + \epsilon$，其中 $\epsilon$ 是噪声，方差为 $\sigma^2$。我们训练出的模型是 $\hat{f}(x)$。那么对于某个测试点 $x$，期望误差可以分解为：

$$
\mathbb{E}\bigl[(y - \hat{f}(x))^2\bigr] = \underbrace{\sigma^2}_{\text{不可约误差}} + \underbrace{\bigl(\text{Bias}[\hat{f}(x)]\bigr)^2}_{\text{偏差}^2} + \underbrace{\text{Var}[\hat{f}(x)]}_{\text{方差}}
$$

其中

$$
\text{Bias}[\hat{f}(x)] = \mathbb{E}[\hat{f}(x)] - f(x),
\qquad
\text{Var}[\hat{f}(x)] = \mathbb{E}\bigl[(\hat{f}(x) - \mathbb{E}[\hat{f}(x)])^2\bigr]
$$

三项的含义：

-   **偏差**：模型在所有可能的训练集上「平均而言」偏离真实函数多远。高偏差意味着模型假设太强、表达不了真实规律，也就是**欠拟合**。
-   **方差**：换一个训练集重新训练，模型预测会变多少。高方差意味着模型太灵活、把训练集的噪声也学进去了，也就是**过拟合**。
-   **不可约误差 $\sigma^2$**：数据本身的噪声，任何模型都消不掉。它给了性能一个硬上界。

一个直观的类比是打靶：

| | 低方差 | 高方差 |
| --- | --- | --- |
| **低偏差** | 靶心附近密集 ✅ | 散布在靶心周围，平均还准 |
| **高偏差** | 密集但整体偏离靶心，稳定地错 | 又偏又散，最差 |

模型的复杂度决定了这个平衡：复杂度升高时，偏差下降、方差上升。**总误差是一条 U 形曲线**，在某个复杂度处最小。这也是为什么「越复杂的模型越好」是错的。

### 七、怎么测算：三个可操作的方法

理论上要算 $\mathbb{E}[\hat{f}]$ 需要无穷多个训练集，实际做不到。但有三个替代手段非常有效。

#### 1. 看训练集和验证集的差距

这是最快的第一步：

| 表现 | 诊断 |
| --- | --- |
| 训练误差高，验证误差也高（接近） | **高偏差**（欠拟合） |
| 训练误差低，验证误差高（差距大） | **高方差**（过拟合） |
| 两者都低且接近 | 合适 |
| 训练误差低，验证误差高，且**两者都随数据增加在改善** | 高方差，加数据有效 |

注意一个常被说错的地方：**「训练误差低」本身不是过拟合的证据**，关键是和验证误差的**差距**。

#### 2. 学习曲线（learning curve）

固定模型，改变训练样本量，同时画训练和验证误差：

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import learning_curve, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

X, y = load_breast_cancer(return_X_y=True)
model = make_pipeline(StandardScaler(), SVC(C=100, gamma="scale"))

train_sizes, train_scores, val_scores = learning_curve(
    model, X, y, cv=StratifiedKFold(5, shuffle=True, random_state=0),
    train_sizes=np.linspace(0.1, 1.0, 6), scoring="accuracy", n_jobs=-1,
)

print(f"{'n_train':>8} {'train':>8} {'valid':>8} {'gap':>8}")
for n, tr, va in zip(train_sizes, train_scores.mean(1), val_scores.mean(1)):
    print(f"{n:8d} {tr:8.4f} {va:8.4f} {tr - va:8.4f}")
```

怎么读这张表：

-   两条曲线**都停在低位且靠得很近**：高偏差。加数据没用，要加特征或提升模型复杂度。
-   两条曲线**差距大，但验证曲线还在上升**：高方差。加数据有效，但更直接的是简化模型或加正则。
-   两条曲线**已经汇合**：加数据不会再带来收益。

#### 3. 验证曲线（validation curve）

固定数据，改变某一个超参数（通常是正则强度或模型复杂度），看训练/验证误差怎么变。它能直接定位最佳复杂度：

```python
from sklearn.model_selection import validation_curve

C_range = np.logspace(-3, 3, 7)
train_scores, val_scores = validation_curve(
    make_pipeline(StandardScaler(), SVC(gamma="scale")),
    X, y, param_name="svc__C", param_range=C_range,
    cv=5, scoring="accuracy", n_jobs=-1,
)

for C, tr, va in zip(C_range, train_scores.mean(1), val_scores.mean(1)):
    print(f"C={C:10.4f}  train={tr:.4f}  valid={va:.4f}")
```

输出会呈现典型的形状：$C$ 很小时（强正则）训练和验证都低——高偏差；$C$ 很大时训练接近 1 而验证下降——高方差。中间验证分数最高的位置就是合适的复杂度。

#### 4. 多次重复训练的方差

还有一个直接估计方差的办法：用不同的随机种子/不同的数据划分重复训练 $M$ 次，看验证分数的**标准差**。

```python
from sklearn.model_selection import train_test_split

scores = []
for seed in range(10):
    X_tr, X_va, y_tr, y_va = train_test_split(X, y, test_size=0.2, random_state=seed)
    model.fit(X_tr, y_tr)
    scores.append(model.score(X_va, y_va))

print("均值:", np.mean(scores).round(4), "标准差:", np.std(scores).round(4))
```

标准差大，说明结论不稳定——即使平均值好看，换一批数据结果可能差很远。这在模型选型时比单次分数更有参考价值。

### 八、高方差怎么办

高方差的本质是「模型对训练集的具体噪声过于敏感」。三个标准方向，按性价比排序：

#### 1. 获取更多数据

**最有效、最不容易用错的方法**。样本量增大时，方差按 $1/N$ 的速度下降。学习曲线上表现为验证曲线继续上升、与训练曲线逐渐汇合。

在拿不到更多真实数据时，还有几个等效手段：

-   数据增强（图像翻转裁剪、文本回译、时序加噪）；
-   半监督 / 自监督预训练；
-   迁移学习（用大数据预训练的权重做初始化）。

#### 2. 简化模型 / 选择较少特征

把模型容量降下来：

-   减少层数、减少每层单元数、减少树深度；
-   做特征选择，删掉噪声特征和高度冗余的特征；
-   对线性模型，用 L1 直接做稀疏筛选。

减少特征这件事在高维小样本（$d \gg N$）时尤其关键。很多「模型不行」的情况其实是「特征里噪声太多」，删掉一半特征反而提升验证分数。

#### 3. 正则化

在不降低模型表达结构的前提下压住方差：

-   L1 / L2 / ElasticNet（调 $\lambda$ 或 `C`）；
-   Dropout、权重衰减；
-   早停（在验证损失开始上升前停止）；
-   树的 min_samples_leaf、max_depth、subsample。

还有两个工程上很常用的手段：**Bagging / 随机森林**（对样本和特征做抽样，平均掉方差）和**集成多个模型**（模型平均天然降低方差）。

#### 4. 一个顺序建议

```
先确认是高方差
  → 加正则（最便宜，先试）
  → 简化模型或减特征
  → 加数据（最贵，但收益最确定）
  → 数据增强 / 迁移学习
```

不要一上来就加数据——如果模型本身结构就不对，加数据只是让错误更稳定。

### 九、高偏差怎么办

高偏差的本质是「模型的假设空间里根本没有真实函数」。这时候加数据没用，学习曲线上两条线会一起停在低位。

#### 1. 添加额外特征

这是最直接的手段。高偏差往往意味着现有特征包含的信息不足以刻画目标：

-   加入原始特征的组合（比值、差值、交互项）；
-   加入领域知识构造的特征（比如做销量预测时加节假日、促销标记）；
-   用 embedding 或预训练模型提取更丰富的表示；
-   检查有没有可用但被漏掉的字段。

判断特征是否有效的方法：单独用它做单变量建模，看是否与目标有显著关系。

#### 2. 减小正则化强度

如果模型容量足够，只是被正则压得太狠：

-   减小 $\lambda$，或增大 `C`（注意 `C` 是倒数，**`C` 越大正则越弱**）；
-   减小 dropout 概率；
-   放宽早停的耐心（patience）；
-   放宽树的最小叶子样本数限制。

验证曲线上表现为：当前处在「左侧低平台」，把复杂度过高一点能让验证分数上升。

#### 3. 提升模型复杂度 / 换模型族

-   线性模型表达不了非线性关系，改用树模型或加多项式特征；
-   树深度不够就加深（但要同时监控方差）；
-   神经网络加宽加深、换更强的结构；
-   用集成（Boosting 提升的是拟合能力，和 Bagging 降低方差的方向不同）。

#### 4. 检查是否是「假的高偏差」

有两种情况看起来像高偏差，实际不是：

-   **特征工程有 bug**：某个特征实际上全是缺失值、或者被错误编码，导致模型没信息可用；
-   **标签有噪声**：如果标签本身错误率很高，训练损失降不下去是正常的，这时该做的是清洗标签而不是加复杂度。

清洗标签的收益经常被严重低估。

### 十、把诊断和处方连起来

整个流程可以压缩成一张表：

| 症状 | 诊断 | 优先动作 |
| --- | --- | --- |
| 训练高、验证高、gap 小 | 高偏差 | 加特征 → 减小正则 → 加复杂度 |
| 训练低、验证高、gap 大 | 高方差 | 加正则 → 简化/减特征 → 加数据 |
| 训练和验证都随数据量上升 | 高方差且数据不足 | 加数据 / 增强 |
| 训练和验证已汇合但都不好 | 高偏差且数据充足 | 换模型族 / 加特征 |
| 验证分数方差大（多 seed 波动） | 不稳定 | 简化模型、增数据、集成 |
| 验证分数出奇地高 | 泄漏 | 先查数据，不要庆祝 |
| 训练损失降不下去 | 优化问题 | 查学习率、梯度、实现 bug |

这套诊断的核心逻辑很简单：**先看 gap，再决定方向**。gap 大是方差问题，gap 小但都差是偏差问题。方向搞反了，做的所有努力都是负收益——给一个欠拟合的模型加正则只会更糟。

### 十一、几个实践中的坑

**1. 用测试集调参**

反复看测试集分数来调模型，等于把测试集变成了验证集。测试集只应该在最末尾用一次。如果必须反复评估，就用交叉验证并在验证集上决策。

**2. 验证集太小**

几百个样本的验证集，指标的置信区间可能宽达 ±5%。看到 1% 的提升就换模型，很可能是在拟合噪声。经验上验证集至少要能容纳几百个正样本。

**3. 只报一个数字**

「准确率 0.87」没有信息量。至少要有：基线是多少、标准差多少、在什么数据分布上、用了什么阈值。缺了这些，这个数字无法用于决策。

**4. 忽视业务代价**

模型指标和业务收益不是一回事。漏判一个欺诈的损失和误杀一个正常用户的损失完全不同，最优阈值应该按代价矩阵算，而不是用 0.5。

**5. 跨分布评估缺失**

训练数据是去年、测试数据是今年，或者训练是 A 城市、上线是 B 城市。同分布评估会给出过于乐观的结论。有条件时应该构造一个「时间外」或「地域外」的测试集单独评估。

**6. 把偏差和方差当成互斥的**

现实中两者同时存在。一个复杂模型可能既过拟合又欠拟合（容量用错了地方）。偏差方差分解是一个**指导方向**的框架，不是精确的归因工具。

### 总结

-   训练集拟合参数，验证集选超参数和模型，测试集只报告一次。**用测试集调参是最常见的评估污染**。
-   划分之前的所有预处理都必须放进 Pipeline；分类要 stratify，时序要按时间切，实体数据要按 group 切。
-   验证分数高得离谱时，第一反应应该是查泄漏，而不是庆祝。
-   基线必须先做平凡基线和简单模型基线，否则无法判断分数好坏；类别不均衡时准确率会骗人。
-   期望误差 = 不可约噪声 + 偏差² + 方差；复杂度升高时偏差降、方差升，总误差呈 U 形。
-   诊断看 gap：**训练验证都差 → 高偏差；训练好验证差 → 高方差**。
-   高方差：更多数据 → 简化模型/减特征 → 正则化（外加 bagging、早停、dropout）。
-   高偏差：添加额外特征 → 减小正则化强度 → 提升模型复杂度；顺带检查标签噪声。
-   方向比努力重要：给欠拟合模型加正则、给过拟合模型加容量，都是负收益。
