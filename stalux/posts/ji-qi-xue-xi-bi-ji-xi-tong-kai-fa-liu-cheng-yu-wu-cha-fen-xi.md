> 机器学习笔记的第九篇。上一篇讲的是「怎么判断模型好不好」，这一篇讲「接下来该做什么」。实际项目里 80% 的收益不来自换模型，而来自误差分析、数据质量和评估指标——这三件事构成了系统层面的工程方法。

### 一、开发迭代：别一上来就优化模型

新手最常见的路径是：拿到任务 → 直接上最复杂的模型 → 反复调参 → 发现效果不行 → 不知道下一步做什么。

有经验的做法是反过来：**先建一个能在几小时内跑通的基线，再让验证集误差告诉你下一步**。

一个可执行的节奏：

1.  **搭 baseline**：最简单的模型（逻辑回归、小树、甚至规则），跑通数据管线，得到验证集上的第一个数字。
2.  **建评估框架**：固定验证集和指标，保证每次改动都能对比。这比模型本身重要。
3.  **误差分析**：手动看错误样本，找出错误集中在哪类输入上。
4.  **针对性改进**：根据误差分析结果决定加数据、加特征、改模型还是改标注。
5.  **重复 3–4**，直到收益边际化。

几个反复出现的教训：

-   **过早优化**。在还不知道错误长什么样的时候调模型容量，是在盲猜。误差分析 1 小时，通常胜过调参 1 天。
-   **没有基线**。没有基线就没有「好」的定义，也就无法判断改动是否有效。
-   **改了多处再评估**。一次改一个变量，否则无法归因。这也是为什么需要版本化管理数据和实验。
-   **盯训练损失**。训练损失降了但验证集不动，说明改动没价值。

### 二、误差分析：用 100 个错误找出方向

误差分析（error analysis）的核心动作非常朴素：**把验证集上判错的样本拿出来，逐个看**。

#### 怎么做

1.  在验证集上跑模型，收集所有错误样本（假阳性 + 假阴性）。
2.  **随机抽 100 个**（如果错误总数少于 100，全看）。100 这个数字来自统计直觉：它能给出类别占比的粗略估计，又不会看不完。
3.  对每个样本记录：属于哪一类错误、输入有什么特征（背景噪声？文字模糊？罕见类别？标注本身错了？）。
4.  统计每一类的占比，按「能修 + 收益大」排序。

一个典型的表长这样：

| 错误类型 | 占比 | 是否易修 | 优先级 |
| --- | --- | --- | --- |
| 夜间/低光照图像 | 32% | 加数据增强、加光照归一化 | 高 |
| 小目标（<32px） | 24% | 提高输入分辨率、改特征图尺度 | 中 |
| 标注错误 | 18% | 清洗标签 | **最高** |
| 类别混淆（猫/狗） | 12% | 加细粒度特征 | 中 |
| 其它 | 14% | — | 低 |

这张表的价值是**把「模型不行」变成「具体要做哪三件事」**。注意排序不只看占比：标注错误只占 18%，但它修起来最便宜、且能同时改善训练和评估，所以优先级最高。

#### 上限分析（ceiling analysis）

如果想估算「修好某个环节能带来多少提升」，可以做一个反向实验：**人为把该环节的输入换成完美结果**，看整体指标能涨多少。

比如一个由「检测 → 分类 → 后处理」组成的流水线，逐个把某一段替换成正确答案：

| 环节 | 该段准确率 | 全流程准确率 | 上限收益 |
| --- | --- | --- | --- |
| 现状 | 88% | 72% | — |
| 检测换成完美 | 100% | 81% | +9% |
| 分类也换成完美 | 100% | 89% | +8% |
| 后处理也换成完美 | 100% | 100% | +11% |

结论很清楚：**先修后处理，再修检测，最后才轮到分类**。这个方法的成本很低（不需要真做出完美模型，只要在测试时喂入正确结果），却能避免把几个月花在收益最小的环节上。

### 三、添加更多数据

当误差分析显示「模型已经在拟合，只是见过的样本不够」时，加数据是最有效的。但要分清几种「加」。

#### 1. 数据增强

不改标签、只改输入，是性价比最高的方式：

-   **图像**：随机裁剪、翻转、旋转、颜色抖动、Cutout/Mixup、RandAugment；
-   **语音**：加噪、变速、变调、SpecAugment（在频谱上遮时间/频率块）；
-   **文本**：同义替换、回译、随机删除/交换词；
-   **表格**：SMOTE 类过采样（要小心，它可能制造不真实的样本）。

关键原则：**增强要模拟真实部署时会遇到的变换**。工业质检里图像不会有随机的 180° 旋转，做了反而引入错误先验。

#### 2. 合成数据

用仿真、渲染或生成模型造数据，在自动驾驶、OCR、语音合成里很常见。风险是**合成分布和真实分布不一致**（sim-to-real gap），通常需要混入一定比例的真实数据，并做域随机化。

#### 3. 收集和重新标注

最有价值但最贵。两个技巧：

-   **主动学习**：优先标注模型最不确定的样本（预测概率接近 0.5 的），标注效率最高；
-   **针对性采集**：误差分析告诉你夜间图像不行，就去采夜间数据，而不是无差别堆量。

#### 4. 「加数据无效」的信号

如果加了数据验证集完全不动，通常是这几种情况：

-   **模型已饱和**（学习曲线汇合）——该加特征或换模型；
-   **加的是同类数据**，没有覆盖到错误集中的那类输入；
-   **标签噪声主导**——再加数据只是加噪声，应该先清洗。

### 四、迁移学习：用别的任务的数据

目标任务数据少，但有一个相关的大数据集（或现成预训练模型）时，迁移学习是最实用的手段。

#### 基本流程

1.  **预训练**：在大规模源数据上训练（或直接用公开权重），学到通用表示；
2.  **替换输出层**：把最后的分类层换成目标任务需要的形状，随机初始化；
3.  **微调**：用目标任务数据继续训练。

#### 冻结策略

| 数据量 | 做法 |
| --- | --- |
| 极少（几百） | **冻结全部骨干**，只训练新输出层；甚至把中间特征抽出来当特征用 |
| 较少（几千） | 冻结前面的层，微调最后几层 |
| 充足（万级以上） | 全网络微调，用较小的学习率（比从头训练小一个数量级） |

#### 为什么有效

浅层学到的是通用特征（边缘、纹理、基础语法），深层才逐渐任务特定。迁移相当于把「通用的那部分」免费拿走，只学「任务特定的那部分」。

需要注意的几点：

-   **域差异越大，收益越小**。ImageNet 预训练对自然图像很好，对医学影像、遥感、显微图像收益有限，但仍常作为初始化。
-   **微调时学习率要小**，否则会破坏预训练权重（灾难性遗忘）。
-   **BatchNorm 的统计量要小心**：小数据微调时，是否冻结 BN 层需要实验验证。
-   **微调阶段仍要保留验证集**，预训练权重也可能带来源域的偏见。

### 五、机器学习项目的完整周期

一个能上线的系统，周期远不止「训练模型」：

```
界定范围 → 收集数据 → 训练与迭代 → 部署 → 监控与维护
   ↑                                        │
   └──────────── 反馈回流 ←─────────────────┘
```

#### 1. 界定范围（scoping）

先明确：要解决什么业务问题、成功标准是什么指标、需要什么数据、可用资源多少。这一步最容易跳过，也最容易导致后面全部白做。**「模型准确率 95%」不是成功标准，「把人工审核量降低 30%」才是**。

#### 2. 数据收集与准备

通常占整个项目 60% 以上的时间。要在这阶段就确认：标签定义是否清晰、标注一致性如何、训练分布和线上分布是否一致。

#### 3. 训练与迭代

就是前面讲的流程：baseline → 误差分析 → 改进。同时要建立可复现的实验管理（数据版本、超参数、随机种子）。

#### 4. 部署

几个工程上的关键点：

-   **推理延迟和吞吐**要满足业务要求（有时比精度更重要）；
-   **模型压缩**：量化、剪枝、蒸馏；
-   **灰度发布**：先小流量验证，再逐步放量；
-   **回滚机制**：新模型有问题能立刻切回旧版本。

#### 5. 监控与维护

上线不是终点。必须监控：

| 监控对象 | 说明 |
| --- | --- |
| 输入分布 | 特征均值/方差漂移，说明数据分布变了 |
| 预测分布 | 输出类别比例突变，可能是上游 bug |
| 业务指标 | 点击率、通过率、人工复核率 |
| 延迟与错误率 | 服务健康度 |

**概念漂移（concept drift）** 是必然发生的：用户行为变了、市场变了、对抗样本出现了。对应做法是定期重训、在线学习，或者建立数据回流机制把线上难例标回训练集。

### 六、公平、偏见与伦理

模型会放大数据里的偏见，这是工程问题，不是道德口号。

#### 偏见从哪来

1.  **历史偏见**：训练数据记录的是过去的不公平决策（比如历史上某群体贷款通过率低）；
2.  **采样偏见**：某些群体在数据里代表性不足；
3.  **标注偏见**：标注者的主观判断带入标签；
4.  **代理变量**：用邮编、姓名等与受保护属性高度相关的特征，间接引入了歧视。

#### 怎么处理

-   **分层评估**：不要只看整体指标，要按群体（性别、年龄、地域）分别看精确率/召回率。整体 AUC 0.9 可能掩盖某个群体只有 0.6。
-   **检查代理特征**：做特征重要性分析，看是否有敏感属性的强代理。
-   **缓解手段**：预处理（重采样、去偏表示）、训练中（公平性约束）、后处理（按群体调整阈值）。三者都有代价，通常要接受一定精度损失。
-   **文档化**：记录模型的适用范围、已知局限、训练数据的时间与来源，避免被用在设计范围之外的场景。

一个实用的默认动作：**指标必须分群体报告**。这既是公平性检查，也常常能暴露数据质量问题。

### 七、倾斜数据集：准确率为什么会骗人

现在换个场景：正类只占 1%（欺诈检测、罕见病筛查、缺陷检测）。

假设模型**把所有样本都判为负类**：

$$
\text{准确率} = \frac{99}{100} = 99\%
$$

这个「模型」什么也没学到，却拿到了 99% 的准确率。这就是倾斜数据集（skewed dataset）下准确率失效的原因。

#### 混淆矩阵

一切指标的基础：

|  | 预测正 | 预测负 |
| --- | --- | --- |
| **实际正** | TP（真阳性） | FN（假阴性，漏判） |
| **实际负** | FP（假阳性，误判） | TN（真阴性） |

由此定义：

$$
\text{Precision} = \frac{TP}{TP + FP},
\qquad
\text{Recall} = \frac{TP}{TP + FN}
$$

$$
F_1 = \frac{2 \cdot P \cdot R}{P + R}
$$

-   **精确率（Precision）**：判为正的样本里，有多少是真的正。回答「报警可信吗」。
-   **召回率（Recall）**：所有真正的正样本里，抓到了多少。回答「漏了多少」。
-   **F1**：两者的调和平均，对低值更敏感（一边接近 0，F1 就接近 0）。

#### 更合适的评估方式

| 做法 | 说明 |
| --- | --- |
| 用 F1 / PR-AUC 替代准确率 | 对少数类更敏感 |
| 保持类别比例的分层划分 | 保证验证集里正样本数量足够 |
| 报告混淆矩阵 | 比单一数字信息量大得多 |
| 固定一个基准率 | 比如「人工审核的精确率」，作为对照 |

一个具体的对照方法：在两个类别比例不同的数据集上（比如 1% 和 5%），**同样的模型精确率会显著不同**，但召回率、AUC 变化较小。所以跨数据集比较时，优先看对先验不敏感的量。

### 八、精确率与召回率的权衡

这两个指标天然对立。把判定阈值调低，更多样本被判为正：

-   召回率上升（漏判变少）；
-   精确率下降（误判变多）。

反之亦然。所以不存在「同时最优」，只存在「在业务约束下最优」。

#### 怎么选

**先问代价**：

| 场景 | 更看重 | 原因 |
| --- | --- | --- |
| 癌症筛查 | 召回率 | 漏诊代价远大于误诊（误诊可复查） |
| 垃圾邮件过滤 | 精确率 | 误杀正常邮件代价大 |
| 欺诈检测 | 看业务 | 通常用代价矩阵加权 |
| 推荐系统召回阶段 | 召回率 | 后面还有精排兜底 |

#### 代价矩阵

如果两类错误代价是 $C_{FN}$ 和 $C_{FP}$，期望代价为：

$$
\text{Cost} = C_{FN}\cdot FN + C_{FP}\cdot FP
$$

最优阈值不是 0.5，而是让边际代价相等的位置。假设正类先验为 $\pi$，则最优判定条件是

$$
P(y=1 \mid x) > \frac{C_{FP}}{C_{FP} + C_{FN}}
$$

举例：漏判一个欺诈损失 1000 元，误判一个正常用户损失 50 元，则阈值为 $\frac{50}{1050} \approx 0.048$——远低于 0.5。这也解释了为什么在不均衡场景直接用 `predict()` 的默认阈值几乎总是错的。

#### PR 曲线与阈值选择

把阈值从 0 到 1 扫一遍，得到 PR 曲线。曲线越靠近右上越好；不同模型之间比较时看 **PR-AUC**（在倾斜数据上比 ROC-AUC 更有区分度）。

实操建议：

1.  在验证集上画出 PR 曲线，标出可接受的精确率下限；
2.  在该约束下取召回率最大的阈值；
3.  把阈值写进部署配置，**不要硬编码 0.5**；
4.  线上按业务指标持续监控，必要时重新校准。

### 九、几个实践中的坑

**1. 用准确率汇报不均衡任务**

这是最普遍的错误。任何分类报告都应该附带类别分布，否则数字无法解读。

**2. 误差分析只看模型输出，不看标签**

相当比例的「错误」是标注错了。先抽样核对标签质量，再去改模型。

**3. 迁移学习不做域适配**

直接把 ImageNet 模型搬到完全不同域的图像上，效果可能不如从零训练一个小模型。域差异大时要先试小样本实验。

**4. 上线后不监控分布**

模型不是部署完就稳定。输入分布漂移几个月后性能会静默下降，没有监控就发现不了。

**5. 只看整体指标不看分组指标**

整体指标可能掩盖了某个子群体上的严重退化，这也是公平性问题的技术来源。

**6. 阈值在训练集上定**

阈值是决策参数，必须在验证集上按业务代价选，然后在测试集上验证。在训练集上定阈值必然偏乐观。

### 总结

-   开发迭代的正确顺序是：baseline → 固定评估框架 → 误差分析 → 针对性改进，而不是直接调最复杂的模型。
-   误差分析要手动看 100 个错误样本并分类统计，配合上限分析判断先修哪个环节。
-   加数据要加「错误集中的那类数据」；数据增强要模拟真实部署时的变换。
-   迁移学习适用于目标任务数据少且源任务相关的场景，冻结策略取决于数据量，微调学习率要小。
-   完整周期包含界定范围、数据、训练、部署、监控；概念漂移是常态，必须有回流与重训机制。
-   公平性检查的默认动作是**分群体报告指标**，它能同时暴露偏见和数据问题。
-   倾斜数据集下准确率会骗人，要用混淆矩阵、Precision/Recall/F1/PR-AUC。
-   精确率与召回率不可兼得，阈值应按代价矩阵算（$\frac{C_{FP}}{C_{FP}+C_{FN}}$），不要硬编码 0.5。
