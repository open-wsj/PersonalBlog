> 这是机器学习笔记的第四篇。第二篇讲梯度下降时简单提过学习率，但那只是「太大太小都有症状」的表格。实际训练时真正难的是**看着一条曲线判断问题出在哪**——这篇就围绕这件事展开。

### 一、学习率到底在控制什么

参数更新式只有一行：

$$
\theta_{t+1} = \theta_t - \eta\, \nabla_\theta J(\theta_t)
$$

$\eta$ 是学习率，决定了每次沿梯度方向**走多远**。它不是模型的一部分，却几乎是最影响训练结果的一个数：

-   它是唯一一个「量级错了就完全训不起来」的超参数。批次大小、层数、宽度都可以慢慢调，学习率差 10 倍往往就是一条能收敛的曲线和一条发散的曲线。
-   它没有通用默认值。同一个 `1e-3`，在 Adam + Transformer 上是标准配置，在未标准化的线性回归上可能直接炸掉。

所以理解学习率，本质是理解**「步长和损失曲面形状之间的关系」**。

### 二、学习率太小：能走对，但走不动

症状很单调，也很好认：

| 现象 | 说明 |
| --- | --- |
| loss 单调下降但极慢 | 曲线平滑、没有毛刺，就是斜率小 |
| 训练很多 epoch 仍远离最优 | 收敛速度约为 $O(1/t)$，$\eta$ 小一倍，同样精度要多走一倍步数 |
| 验证指标长期不动 | 容易被误判成「模型容量不够」或「数据有问题」 |

学习率过小时**不会出错，只会浪费时间**。它是安全的错误，所以常常被忽略——尤其是在算力充足、习惯「多训一会儿」的情况下，很多人会把一个本可以 10 个 epoch 收敛的任务训到 200 个 epoch。

一个快速的判断方法：把学习率乘 3 或乘 10 再跑几百步，如果 loss 明显降得更快且不发散，说明原来的值就是偏小了。

### 三、学习率太大：两种典型的病态曲线

这才是标题里说的重点。同样是「学习率太大」，曲线的形状其实分两种，含义完全不同。

#### 情况一：整体在降，但带周期性尖峰

![学习率偏大时的损失曲线：整体下降，但每次更新后出现尖峰，后期开始抬升](/images/ml/lr-too-large-oscillate.png)

这条曲线的特征：

-   loss 的大趋势是**往下走的**，说明方向没错；
-   但每隔一段就冒出一个尖峰，然后又落回去，像在锯齿上行走；
-   到后面尖峰越来越高，整体开始往上翘。

它的物理图像是：参数在最优点的两侧**来回跨越**。当前点在山谷的这侧，梯度指向对面，一步跨过了谷底，落到对面更高的位置；下一步梯度反过来，又跨回去。因为步长略大于「刚好跨到对面同高」的长度，每次都会多冲一点，误差被逐渐放大，最后脱离收敛区域。

换句话说，**学习率已经接近临界值**。这种状态最危险，因为前几百步看起来「虽然在抖但确实在学」，很容易被忽略，直到训练后期突然崩掉或者指标卡住不动。

#### 情况二：几乎不降，直接单调发散

![学习率过大时的损失曲线：起始略微平缓，随后单调上升直至发散](/images/ml/lr-too-large-diverge.png)

这条曲线一开始几乎是平的，然后单调往上飙，标注也直接写了「$\alpha$ is too large」。

含义很直接：**每一步都比上一步更差**。更新后的参数不仅没让损失下降，反而让损失变大，然后在更差的位置算出更大的梯度，下一步更糟——正反馈，几步之内就溢出成 `nan` 或 `inf`。

为什么一定会这样？回到一阶泰勒展开：

$$
J(\theta - \eta g) \approx J(\theta) - \eta \lVert g \rVert^2
$$

这个近似只在 $\eta$ 足够小时成立。严格地说，若损失函数在局部是 $L$-光滑的（Hessian 最大特征值不超过 $L$），则保证下降的条件是

$$
\eta < \frac{2}{L}
$$

一旦 $\eta$ 越过这个上界，二次项占据主导，$J(\theta - \eta g) > J(\theta)$ 就成立了。所以发散不是玄学，是**步长超过曲面曲率允许的上限**。

两种情况对照着看，其实就是同一条临界线的两侧：

| 曲线形状 | 学习率位置 | 本质 |
| --- | --- | --- |
| 平滑下降 | 远小于临界值 | 安全但慢 |
| 下降 + 周期性尖峰 | 略小于临界值 | 在谷底两侧振荡 |
| 先平后单调上升 | 大于临界值 | 每步都在放大误差 |

### 四、先别急着调学习率：这些 bug 也会画出同样的曲线

这是实践中比理论更重要的一条：**一条看起来很糟的曲线，有一半概率根本不是学习率的问题**。下面这些代码问题制造出来的曲线，和前两种几乎无法用肉眼区分。

**1. 累积 loss 没有除以步数**

最常见的误判来源。如果每步记录的是 `loss_sum += loss` 而不是 `loss_sum / count`，或者滑动平均的窗口写错，画出来的曲线会呈现「阶梯上升」的形状——真正的 loss 在降，但累加值在涨。

**2. 忘了清梯度（PyTorch）**

```python
# 错误：梯度会跨 batch 累积
for x, y in loader:
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
```

`backward()` 默认是**累加**梯度，不清零的话等效于学习率被逐步放大，训练到中途必然爆炸。正确写法是每步 `optimizer.zero_grad()`（或 `set_to_none=True`）之后再 `backward`。

**3. loss 的定义和任务不匹配**

比如多分类用了 `BCELoss` 却没做 sigmoid、回归忘了把 `reduction` 从 `sum` 改成 `mean`、标签被 one-hot 了但模型输出是 logits。这些错误让 loss 的数值量级整体偏移，表现为「能降但降不到低位」或者「一开始就很大然后缓慢上升」。

**4. 标签/特征错位**

`DataLoader` 的 `shuffle` 和自定义 `collate_fn` 配合出错、数据增强同时作用到了 X 和 y、train/valid 划分后索引错乱。典型症状是训练 loss 正常下降、验证 loss 完全不降甚至上升，而降低学习率只是让这个现象变慢。

**5. 特征未缩放**

上一篇专门讲过。量纲差异巨大时，同一个学习率对某个维度合适、对另一个维度就是发散，曲线表现为尖峰式和整体下降的混合——和「学习率临界」长得一模一样。

**6. 学习率作用到了不该作用的参数**

比如把 `bias`、`BatchNorm` 的 `weight` 也丢进了带 weight decay 的参数组，或者给预训练部分和随机初始化部分用了同一个学习率。后者常表现为前期正常、某个阶段突然恶化。

排查顺序建议是：

1.  打印当前实际生效的 `lr`（不是你以为的那个值），确认调度器没有把它改成极小或极大；
2.  拿**一个 batch** 反复训练几十步，看 loss 能不能降到接近 0——降不下去说明是代码或模型问题，不是学习率；
3.  检查 `zero_grad`、`loss` 的 reduction、标签对齐这三件事；
4.  再回来调学习率。

一个 batch 过拟合是最有效的分诊手段，几行代码就能把「优化问题」和「实现问题」分开。

### 五、怎么把合适的学习率找出来

#### 1. 学习率扫描（LR range test）

从很小的值开始，每个 batch 把学习率乘一个固定倍数往上走，记录 loss，画出来找**下降最陡的那一段**。实践中通常取「最陡斜率处」往左一点的值。

```python
import torch

def lr_range_test(model, loader, criterion, optimizer, start=1e-6, end=1.0, steps=200):
    lrs, losses = [], []
    gamma = (end / start) ** (1 / steps)
    lr = start
    for param_group in optimizer.param_groups:
        param_group["lr"] = lr
    for i, (x, y) in enumerate(loader):
        if i >= steps:
            break
        optimizer.zero_grad()
        loss = criterion(model(x), y)
        loss.backward()
        optimizer.step()

        lrs.append(lr)
        losses.append(loss.item())
        lr *= gamma
        for param_group in optimizer.param_groups:
            param_group["lr"] = lr

    return lrs, losses
```

画出来是一条先缓慢下降、到某点后急剧上升的曲线；急剧上升的起点就是临界值，取它左侧约一个数量级作为初始学习率比较稳。

#### 2. 先粗后细

按 $10^{-5}, 10^{-4}, \dots, 10^{-1}$ 各跑几百步，挑收敛最快且不震荡的，再在它附近按 3 倍间隔细调。比随机试要高效得多。

#### 3. 直接观察前 100 步

不用等整个 epoch。把 loss 按 step 画出来，前 100 步就能判断：平滑下降 → 偏小或合适；有规律尖峰 → 偏大；单调上升 → 严重偏大。前面两张图就是这个判断的模板。

### 六、学习率调度：让步长随训练阶段变化

固定学习率必然在某个阶段不合适：前期需要大步快速接近，后期需要小步精调。常见的调度策略：

| 策略 | 形状 | 适用 |
| --- | --- | --- |
| Step / MultiStep | 每隔若干 epoch 乘 0.1 | 传统 CNN 训练，简单可控 |
| Cosine Annealing | 余弦曲线缓降到接近 0 | 现代主流，无需手动定衰减点 |
| Warmup + Cosine | 前若干步线性升到峰值，再余弦降 | Transformer 类模型的标配 |
| OneCycle | 先升后降，单周期 | 收敛快，适合固定训练预算 |
| ReduceLROnPlateau | 指标停滞时自动降 | 不确定训练长度时省心 |

PyTorch 里最省事的是把调度器和优化器一起用：

```python
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)
scheduler = torch.optim.lr_scheduler.OneCycleLR(
    optimizer, max_lr=1e-3, total_steps=len(loader) * epochs
)

for epoch in range(epochs):
    for x, y in loader:
        optimizer.zero_grad()
        loss = criterion(model(x), y)
        loss.backward()
        optimizer.step()
        scheduler.step()          # OneCycleLR 按 step 更新
```

一个容易搞错的点：`StepLR`、`CosineAnnealingLR` 通常按 **epoch** 调 `step()`，而 `OneCycleLR` 必须按 **batch/step** 调。调错了调度器，曲线看起来会像学习率一直在错误的位置——又是一次「像学习率问题、其实是代码问题」。

**Warmup 为什么重要**：训练初期参数是随机初始化的，梯度方向噪声很大，直接上大学习率容易把模型带进坏区域。先用很小的学习率热身几百步，等统计量稳定（尤其是 BatchNorm 的 running stats）再升到峰值，能显著降低发散概率。

### 七、学习率和 batch size 的关系

这两者是绑在一起的。batch 越大，梯度的方差越小，估计越准，理论上可以用更大的步长。经验规则是**线性缩放**：

$$
\eta_{\text{new}} = \eta_{\text{base}} \cdot \frac{B_{\text{new}}}{B_{\text{base}}}
$$

比如 batch 从 32 增到 256，学习率可以乘 8。batch 特别大时（几千以上）线性规则会过于激进，改用平方根缩放 $\eta \propto \sqrt{B}$ 更稳。此外，大 batch 通常还需要配合 warmup，否则前几步的大梯度会直接把模型推飞。

反过来说，如果改了 batch size 却没动学习率，曲线出现异常时**先怀疑这里**，而不是急着换优化器。

### 八、不同优化器的学习率量级

同样是「合适的学习率」，不同优化器差好几个数量级，不能照抄：

| 优化器 | 典型初始学习率 | 说明 |
| --- | --- | --- |
| SGD（无动量） | $10^{-2} \sim 10^{-1}$ | 对缩放敏感，常配合动量 |
| SGD + Momentum | $10^{-2} \sim 10^{-1}$ | 动量 0.9 左右 |
| Adam / AdamW | $10^{-4} \sim 10^{-3}$ | 自适应，$3\times10^{-4}$ 是常见起点 |
| RMSProp | $10^{-4} \sim 10^{-3}$ | 类似 Adam |

Adam 之所以能用更小的学习率，是因为它按维度对梯度做了归一化，等效步长已经被缩放过了。所以「SGD 用 0.1、Adam 用 0.001」不是玄学，而是两套不同的步长定义。换优化器时一定要重扫学习率，不要沿用旧值。

### 总结

-   学习率控制步长，是唯一一个量级错了就完全训不起来的超参数。
-   太小：平滑但极慢，安全地浪费时间；太大：两种曲线——**带尖峰的下降**（接近临界）和**单调发散**（超过临界）。
-   临界值有理论依据：局部 $L$-光滑时要求 $\eta < 2/L$，超过就每步放大误差。
-   但曲线异常不等于学习率问题：忘清梯度、loss 累加没平均、标签错位、特征未缩放都会画出几乎一样的图。先用**单个 batch 能否过拟合**做分诊。
-   找值靠学习率扫描，长期训练靠调度（Cosine / OneCycle / Warmup），改 batch size 记得同步改学习率。
-   换优化器必须重扫学习率，量级差 100 倍是常态。
